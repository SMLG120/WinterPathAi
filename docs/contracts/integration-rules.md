# Integration rules — contract v1

## 1. Ownership (exclusive write access)
| Agent | Branch | Worktree | Owns |
|---|---|---|---|
| data | `agent/data` | `../winterpath-data` | `data/`, `db/`, `services/ingestion/` |
| routing | `agent/routing` | `../winterpath-routing` | `services/api/`, `services/routing/` |
| ml | `agent/ml` | `../winterpath-ml` | `services/ml/`, `models/` |
| frontend | `agent/frontend` | `../winterpath-frontend` | `apps/web/`, `assets/3d/` |
| platform | `agent/platform` | `../winterpath-platform` | `infra/`, `.github/`, `tests/integration/`, `docker-compose.yml`, root `Makefile` |
| coordinator | `integration/winterpath` | main checkout | `docs/contracts/`, `docs/architecture.md`, `docs/ux-spec.md`, `docs/data-sources-and-licenses.md`, `docs/agents/`, `CLAUDE.md`, `.env.example`, `.gitignore`, `scripts/` |

Every agent may additionally write **only** `docs/agent-reports/<own-name>.md`.
Data agent may append rows to `docs/data-sources-and-licenses.md` **only via a change request**, not directly.
`scripts/check-ownership.sh <name>` fails if a branch touches files outside its paths; it is a merge gate.

## 2. Dependency boundaries
- `services/routing` is a pure Python library (graph in → route out). No FastAPI imports. Reads graph via an interface `GraphProvider` with two impls: `FixtureGraphProvider` (GeoJSON from `data/fixtures/pilot_mini`) and `PostgisGraphProvider`.
- `services/api` imports `services/routing` and `services/ml` inference interface (`winterpath_ml.inference.RiskProvider`). Until ML lands, API uses `NullRiskProvider` returning `unknown`.
- `services/ml` never imports the API. Inference reads only versioned artifacts listed in `models/registry.json`.
- `apps/web` talks to the API only through the client generated from `docs/contracts/openapi.yaml` (`openapi-typescript` + fetch). Mock mode uses MSW handlers whose payloads validate against the schema and are labelled fixture data.
- Python packages: `winterpath_ingestion`, `winterpath_routing`, `winterpath_api`, `winterpath_ml`; each its own `pyproject.toml` (uv), Python 3.12.

## 3. Contract change process
1. Agent writes `docs/agent-reports/<name>.md#change-request` describing the change and why; stops that piece of work (continues other work).
2. Coordinator reviews compatibility, edits contract on `integration/winterpath`, bumps `info.version` (minor for additive, major for breaking), commits.
3. Coordinator propagates by asking each affected agent to `git merge integration/winterpath` (never rebase/force).
Agents **never** edit `docs/contracts/*` themselves.

## 4. Environment isolation
Git worktrees isolate files only. Runtime isolation:

| Agent | API port | Web port | Postgres DB (shared container, port 55432) | Extra |
|---|---|---|---|---|
| data | 8101 | — | `wp_data` | `DATA_DIR=../winterpath-data/data` |
| routing | 8102 | — | `wp_routing` | |
| ml | 8103 | — | `wp_ml` | `MODEL_ARTIFACT_DIR=models/artifacts` |
| frontend | 8104 (mock) | 5174 | — | `VITE_API_BASE_URL=http://localhost:8104/api/v1` or MSW |
| platform | 8105 | 5175 | `wp_platform` | |
| integration | 8100 | 5173 | `wp_integration` | |

Each worktree gets an untracked `.env.local` generated by `scripts/create-worktrees.sh`. No real secrets are placed there; DB password is a random local dev value.

## 5. Merge gates (coordinator)
1. `scripts/check-ownership.sh <name>` passes.
2. Agent report exists with branch SHA, literal test output, blockers, licence notes.
3. Unit tests re-run by coordinator in the agent's worktree pass.
4. Contract tests (Platform) pass against the branch where applicable.
5. No secrets (`gitleaks`/manual grep), no raw data, no files >5 MB.
6. Merge with `git merge --no-ff agent/<name>` into `integration/winterpath`, one at a time. Default order Data → ML → Routing → Frontend → Platform. Re-run integration tests after each.
Never: `--force`, `reset --hard`, `push`, deploy.

## 6. Status vocabulary
`NOT STARTED`, `WORKING`, `BLOCKED`, `TESTING`, `READY FOR REVIEW`, `MERGED` — derived from commits, reports and test output only.
